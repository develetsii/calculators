# Calculators - Un proyecto creado entre todos

**Aprender haciendo. Compartir conocimiento. Construir en comunidad.**

Este repositorio es un proyecto colaborativo de nuestra asociación de desarrollo de software, formado por estudiantes universitarios con ganas de aprender, experimentar y mejorar sus habilidades programando.

Nuestro objetivo es construir un proyecto vivo que evolucione con las ideas, el trabajo y las aportaciones de sus integrantes. No buscamos únicamente desarrollar una aplicación, sino crear un espacio donde aprender de los demás, poner en práctica nuevas tecnologías y descubrir cómo se trabaja en un proyecto de software real.

No importa si estás empezando con Angular o si ya tienes experiencia: **lo importante es tener ganas de aprender, colaborar y aportar.**

</br>

## 🌱 Un proyecto en constante evolución

Este repositorio no es un producto cerrado ni una aplicación con un alcance definitivo. Es un espacio de experimentación y aprendizaje que queremos hacer crecer entre todos.

Habrá ideas que funcionen, otras que necesiten cambios y propuestas que nos permitan descubrir formas mejores de resolver un problema. Lo importante es compartir el proceso, aprender de los errores y construir sobre el trabajo de los demás.

**Si tienes una idea, proponla. Si quieres aprender, participa. Si encuentras algo que mejorar, abre una PR.**

Cada contribución es una oportunidad para aprender y ayudar a que el proyecto avance.

</br>

## 🤝 Cómo contribuir
Todas las aportaciones son bienvenidas, independientemente de tu experiencia o disponibilidad. Puedes contribuir proponiendo ideas, reportando errores o desarrollando nuevas funcionalidades por tu cuenta.

Algunas formas de participar:

- Proponer nuevas funcionalidades o mejoras.
- Reportar errores y problemas.
- Mejorar la interfaz y la experiencia de usuario.
- Refactorizar código y aplicar buenas prácticas.
- Añadir pruebas.
- Mejorar la documentación.
- Experimentar con Angular y compartir lo aprendido.

### Proponer ideas y mejoras
Si tienes una idea o encuentras algo que podría mejorarse, puedes abrir una **Issue** explicando tu propuesta o el problema que has encontrado.

No necesitas escribir código para contribuir. Las ideas y sugerencias también ayudan a que el proyecto evolucione.

### Contribuir con código

Si quieres implementar una mejora, puedes trabajar en ella individualmente y enviar una Pull Request (PR) para que el resto de integrantes la revise.

El proceso es sencillo:

1. **Explora el proyecto.** Familiarízate con el código y las funcionalidades existentes.
2. **Revisa las Issues abiertas.** Comprueba si alguien ya ha propuesto algo similar. Para cambios importantes, abre una Issue antes de empezar y comenta tu propuesta.
3. **Crea una rama.** Trabaja en una rama independiente para mantener tus cambios separados de la rama principal.
4. **Implementa y prueba tus cambios.** Desarrolla la solución y comprueba que funciona correctamente.
5. **Abre una Pull Request.** Explica qué has cambiado y cómo se puede probar.
6. **Revisa el feedback.** Otros integrantes podrán hacer sugerencias o solicitar cambios antes de aprobar la PR.
7. **Integra los cambios.** Cuando la PR cumpla los criterios del proyecto y reciba la aprobación necesaria, se podrá incorporar a la rama principal.

Para cambios pequeños, como corregir un error tipográfico, puedes abrir una PR directamente sin crear una Issue previamente.

### Un proyecto para aprender

No esperamos que todo el mundo tenga experiencia previa ni que las primeras contribuciones sean perfectas. Las revisiones forman parte del proceso y sirven para compartir conocimientos, descubrir otras formas de resolver problemas y mejorar el código entre todos.

Puedes contribuir cuando tengas tiempo, trabajar por tu cuenta y participar tanto como quieras. Lo importante es mantener una buena comunicación y estar abierto a aprender de los demás.

**Si tienes una idea, compártela. Si quieres mejorar algo, anímate a contribuir.**

Ejemplo de flujo de trabajo:

```bash
git checkout -b feature/my-feature

# Implement your changes

git add .
git commit -m "add my feature"
git push -u origin feature/my-feature
```

Después, abre una Pull Request desde tu rama hacia la rama principal del repositorio.

**Una Pull Request no tiene que ser perfecta desde el principio.** Las revisiones forman parte del aprendizaje: preguntar, recibir sugerencias y mejorar el código es precisamente lo que queremos fomentar.

## 🚀 Empezar a desarrollar

¿Quieres explorar el proyecto o empezar a contribuir? Sigue estos pasos para ponerlo en marcha en tu entorno local.

### Requisitos previos

Necesitarás tener instalado:

- [Node.js](https://nodejs.org/) en una versión compatible con Angular 20.
- [Angular CLI](https://angular.dev/tools/cli) 20.3.6 o una versión compatible.
- [Git](https://git-scm.com/).

</br>

### Instalación

Clona el repositorio y accede al directorio del proyecto:

```bash
git clone https://github.com/develetsii/calculators.git
cd calculators
```

Instala las dependencias:

```bash
npm install
```

Inicia el servidor de desarrollo:

```bash
ng serve
```

Abre [http://localhost:4200/](http://localhost:4200/) en tu navegador. La aplicación se actualizará automáticamente cuando modifiques los archivos del proyecto.

</br>

## 📐 Buenas prácticas

Para que el proyecto sea fácil de mantener y ampliar, intentaremos seguir estas pautas:

- Escribir código claro, legible y fácil de mantener.
- Mantener los componentes y servicios enfocados en responsabilidades concretas.
- Reutilizar código cuando tenga sentido, evitando abstracciones innecesarias.
- Añadir o actualizar pruebas cuando corresponda.
- Documentar las decisiones importantes y los cambios que no sean evidentes.
- Mantener las Pull Requests enfocadas en cambios concretos y fáciles de revisar.
- Respetar las opiniones de los demás y proporcionar feedback constructivo.

No esperamos que todo el mundo conozca estas prácticas desde el primer día. Queremos aprenderlas y aplicarlas juntos.
